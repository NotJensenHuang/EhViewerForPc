# 漫画翻译 DirectML 会话复用验证（2026-11-25）

## 实现

PaddleOCR 识别模型的批次和输入宽度为自由维度。DirectML 在会话初始化时取得确定形状，可把依赖输入尺寸的优化提前完成。固定检测图尺寸的探针没有稳定收益，固定识别宽度的探针缩短了热态识别。四张样本的 OCR 文本与区域坐标一致。[ONNX Runtime DirectML 性能说明](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html#performance-tuning)

工作进程用动态会话完成首张文字页，后续页为重复出现的宽度编译并复用至多 8 个固定形状会话。其他宽度沿用动态会话。固定形状编译或运行失败时释放专用会话并回退至动态 DirectML。首图、同一宽度的候选生成及 CTC 解码使用原尺寸和相同的识别规则。工作进程退出时一并释放会话。

## Windows x64 NativeAOT 对照

测试平台为 Windows 11 x64、NVIDIA GeForce RTX 5070 Ti、驱动 617.14，显存 16,303 MiB。基线和优化版使用同一套打包运行库、模型与简体中文设置。每个工作进程依次处理 4 张真实页 PNG，再处理一次第一张页图。7B 基线和候选交替测量，各 3 个工作进程。1.8B 各测 1 个工作进程。表中每行先合计单进程的指定页面，再取中位数；1.8B 为单次读数。系统磁盘缓存和驱动运行状态会影响首图时延。

| 指标 | 7B 基线 | 7B 优化 | 1.8B 基线 | 1.8B 优化 |
| --- | ---: | ---: | ---: | ---: |
| 首图整页 | 4.801 秒 | 5.033 秒 | 3.311 秒 | 3.289 秒 |
| 第 2 图整页，优化版首次编译专用会话 | 2.669 秒 | 3.785 秒 | 3.063 秒 | 2.883 秒 |
| 第 2 至 5 图整页合计 | 6.742 秒 | 5.840 秒 | 8.101 秒 | 4.649 秒 |
| 第 2 至 5 图 OCR 合计 | 4.904 秒 | 3.939 秒 | 6.950 秒 | 3.639 秒 |
| 第 3 至 5 图整页合计 | 4.073 秒 | 1.933 秒 | 5.038 秒 | 1.766 秒 |

整页计时从提交 PNG 到收到工作进程响应，包含 DirectML OCR、按需加载 Vulkan 模型和翻译，应用生成 PNG、界面绘制和最近页结果缓存均在计时区间外。两版识别出每页 4、22、11、4 个区域，文本与坐标逐项相同。翻译采样带随机性。7B 基线的第一个冷样本达到 8.825 秒，第三轮基线的三张热页也有明显波动。首次编译专用会话会占用后续页的一部分时延。

`nvidia-smi` 每 250 毫秒采样整卡，覆盖桌面及其他进程。7B 三轮中最高显存读数为基线 8,965 MiB、优化版 9,017 MiB。1.8B 单轮峰值分别为 5,486 MiB 与 5,748 MiB。测试仅覆盖此显卡和驱动，Windows 10、AMD 与 Intel 设备尚未实测。

在首次提交和同一进程处理过一页后，分别于提交约 160 毫秒时取消。两次收到取消响应分别耗时 363 毫秒和 299 毫秒，之后同一个进程均能成功处理下一页并正常退出。见 `.qa/reader-actions-20261125/worker-cancel.json`。

脚本与原始计时位于 `.qa/reader-actions-20261125/`，包括 `bench-ocr.py`、`bench-ocr-width.py`、`bench-worker.py` 和 `worker-bench.json`。脚本核对样本字节长度、修改时间和 SHA-256 保持一致。基线是同一源码上接入固定形状会话前的 NativeAOT `ui-aot` 产物。

~~~powershell
dotnet publish src/EhViewerForPc -c Release -r win-x64 -p:PublishAot=true -o .qa/reader-actions-20261125/final-release
python .qa/reader-actions-20261125/bench-worker.py .qa/reader-actions-20261125/final-release/EhViewerForPc.exe
python .qa/reader-actions-20261125/bench-cancel.py
~~~
