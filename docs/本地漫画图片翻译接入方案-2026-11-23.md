# 本地漫画图片翻译接入方案

2026-11-23

> 实施阶段按后续需求启用 GPU。当前入口使用 DirectML OCR 与 Vulkan 翻译，仍由用户手动触发静态单页。现行配置见 [README](../README.md#准备本地漫画翻译后端)，验证见 [本地漫画翻译实测](本地漫画翻译实测-2026-11-23.md)。下文为立项时的原始方案。

## 推荐决策

首版在阅读器增加「翻译本页」。用户打开本地漫画或已加载的在线漫画页后，可在原图旁查看按阅读顺序排列的编号、原文和译文，并复制文本。默认在 Windows x64 的 CPU 上运行，模型按需安装。翻译期间，图片、对白和译文均留在本机。

推荐用 **Paddle PP-OCRv5 Mobile + 腾讯 Hy-MT2-1.8B GGUF Q4_K_M + 本机 llama.cpp** 验证日文漫画译简体中文。视觉端检测并识别文字，再按气泡、旁白和阅读顺序组织。翻译端接收区块编号、对白及少量相邻上下文，返回对应译文。英文可复用文本翻译端，等英文漫画 OCR 样本通过后再开放。首版范围是当前静态页。图内叠层、停稳后自动翻译、清字与嵌字按使用反馈逐步推进。

| 决策 | 选型 | 通过条件 |
| --- | --- | --- |
| 视觉 | PP-OCRv5 Mobile 检测与识别 | 日文纵排、小字和多栏能定位、识别并排序 |
| 翻译 | 官方 Hy-MT2-1.8B Q4_K_M | 实机资源占用可接受，中文人工复核通过 |
| 运行 | 应用服务调度本机 worker，模型按需加载 | 断网可用，翻页取消与退出收尾可复现 |
| 展示 | 原图旁的编号与双语结果 | 保持现有缩放、进度和滚动行为 |

## 模型选型

### 日文 OCR 与漫画布局

PP-OCRv5 Mobile 的官方 ONNX 检测和识别权重采用 Apache-2.0。两组权重解决文本行的定位和识别，漫画仍需将文本行归到气泡或旁白，判断纵排、跨栏顺序并处理拟声词。若日文气泡识别偏弱，可对照用于日文气泡与旁白裁剪识别的 manga-ocr，或覆盖日、英、中的 Baberu OCR。若错序集中在气泡、正文与拟声词混合处，可对照 Apache-2.0 的 Koharu 日漫布局权重。[PP-OCRv5 Mobile 检测](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_det_onnx) · [PP-OCRv5 Mobile 识别](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec_onnx) · [manga-ocr](https://huggingface.co/kha-white/manga-ocr-base) · [Baberu OCR](https://huggingface.co/genshiai-daichi/baberu-ocr) · [Koharu 布局权重](https://huggingface.co/mayocream/koharu-layout-highres)

### 文本翻译与敏感对白

腾讯于 2026-05-21 发布 Hy-MT2。1.8B 是 Apache-2.0 的文本翻译模型，支持日文和英文直接译简体中文，图片输入由 OCR 处理。官方 GGUF 的 Q4_K_M 约 1.13 GB，Q8_0 约 1.91 GB，均为权重文件大小。峰值内存需实测，受上下文、计算缓冲和推理后端影响。默认测 Q4_K_M，若发现量化明显影响译质，再对照 Q8_0。官方 2-bit 和 1.25-bit 权重依赖专门算子，标准 Windows x64 工具链的兼容性还需验证。llama.cpp 上游提供 Windows x64 CPU 及 CUDA、Vulkan 发行物，首轮以 CPU 建立基线。[腾讯 Hy-MT2](https://github.com/Tencent-Hunyuan/Hy-MT2) · [官方 GGUF](https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF/tree/main) · [llama.cpp 发行页](https://github.com/ggml-org/llama.cpp/releases)

离线性和敏感对白忠实度分别验收。官方模型在本机推理时仍可能拒译、删句、淡化或扩写。优先用约 1.13 GB 的日→简中漫画单对白微调版做同体量对照。作者说明自己不懂中文，评估依赖自动评判，投入使用前应补中文人工复核和跨气泡上下文测试。[日漫单对白微调模型卡](https://huggingface.co/fumetodev/Hy-MT2-1.8B-JP-Manga-Finetune-chinese-zh-Hans-v1-GGUF)

若仍需专门比较拒译表现，可追加社区 Hy-MT2-7B Abliterated 的 Windows 可用格式 GGUF，Q4_K_M 文件约 4.62 GB，作者未给出译质评估，须复核语义保真和本机资源占用。本次查到的同名 1.8B 消融权重为 Apple 工具链的 MLX 格式，尚未确认该特定版本存在公开的 GGUF 权重。[7B 社区 GGUF](https://huggingface.co/alexwkleung/Hy-MT2-7B-Abliterated-GGUF) · [1.8B 社区 MLX](https://huggingface.co/mlx-community/Hy-MT2-1.8B-Abliterated-8bit)

### 最快的整页对照

先在独立的 `.qa/` 下用漫画样本运行 manga-image-translator 的 CLI 或 HTTP 服务。选择本地检测与 OCR，尝试用它的 `custom_openai` 接本机 llama-server 和 Hy-MT2，先核对提示模板与响应解析。该组合尚未联调。准备好权重后断网重跑，记录分区、原文、译文以及整页可读性。[manga-image-translator](https://github.com/zyddnys/manga-image-translator) · [HTTP 服务入口](https://github.com/zyddnys/manga-image-translator/blob/main/server/main.py) · [本机端点实现](https://github.com/zyddnys/manga-image-translator/blob/main/manga_translator/translators/custom_openai.py)

manga-image-translator 为 GPL-3.0，其列出的 NLLB-600M 权重采用 CC-BY-NC-4.0，方案将该权重排除在发行包之外。清字与嵌字可用 GPL-3.0 的 BallonsTranslator 在 Windows 做独立对照，其无头批处理仍依赖 Qt。Koharu 的 Rust 流水线采用 MIT OR Apache-2.0 并提供无头示例，可参考流水线设计，接口稳定性仍待确认。拟发行的代码、权重、运行时与字体逐项核查授权和分发条件。[manga-image-translator](https://github.com/zyddnys/manga-image-translator) · [BallonsTranslator](https://github.com/dmMaze/BallonsTranslator/blob/dev/README_EN.md) · [Koharu 许可](https://github.com/koharu-rs/koharu/blob/main/Cargo.toml) · [Koharu 无头示例](https://github.com/koharu-rs/koharu/blob/main/crates/koharu-pipeline/examples/run.rs)

## 接入 EhViewer for PC

1. **使用已显示页的输入。** 现有 `IReaderSource` 统一阅读入口。本地库与下载目录读取本地候选，在线页经现有加载服务取得缓存、匹配的本地副本或站点图片。建议在成功显示时记录实际采用的文件版本，翻译命令按需以只读方式取得有限的独占输入。在线快照失效时，提示重新打开该页。现有在线 `LoadAsync` 首次调用会先解析站点页引用，预取也共享图像请求接口，因此推理由当前页命令单独发起。用实际输入内容标识缓存，覆盖本地备选文件和在线请求画质回退。[阅读器来源](../src/EhViewerForPc/Services/ReaderSources.cs#L107) · [在线请求与缓存回退](../src/EhViewerForPc/Services/OnlineImageService.cs#L451) · [预取](../src/EhViewerForPc/Controls/ZoomPanView.cs#L445)
2. **把作业交给应用服务。** 在现有阅读器页头绑定 `ReaderViewModel` 命令，单页和连续模式沿用当前页选择逻辑。拟新增由 `AppServices` 持有的翻译服务，同一时刻运行一页。翻页、内容替换、离开活动阅读器或显式禁用时取消，发布结果前在 UI 线程复核页身份。应用退出等待实际推理或子进程终止，再释放输入缓冲。解码缓冲纳入现有图像预算，推理张量和子进程内存独立限额和测量。[阅读器页头](../src/EhViewerForPc/Views/MainWindow.axaml#L52) · [活动阅读器切换](../src/EhViewerForPc/Views/MainWindow.axaml.cs#L541) · [应用退出](../src/EhViewerForPc/App.axaml.cs#L195) · [图像预算](../src/EhViewerForPc/Services/ImageMemoryBudget.cs#L26)
3. **保持页坐标稳定。** 结果携带区块编号、应用 EXIF 方向后的归一化多边形、原文和译文，先在原图旁显示。后续图内叠层共用图片绘制矩形、缩放、平移与裁剪，连续模式继续使用虚拟化列表。图像与译文共享同一坐标和页身份，避免长条分片、横向反排和缩放造成错位。[阅读器页面模板](../src/EhViewerForPc/Views/ReaderPage.axaml#L17) · [单页绘制](../src/EhViewerForPc/Controls/ZoomPanView.cs#L523) · [连续页绘制](../src/EhViewerForPc/Controls/AsyncImage.cs#L340)
4. **按需装载模型，控制本地留存。** 推荐以可选本地包提供 llama.cpp 与固定版本模型，安装或导入时核对文件哈希，推理只使用本机文件。OCR worker 可用标准输入输出传递有界图像与结构化结果；若采用 llama-server，服务端和应用端均固定到本机回环地址。首版使用有界会话内缓存。若增加磁盘缓存，结果与模型分开存放于 `AppPaths`，键纳入实际内容哈希、语言、模型与流水线版本，在线结果按站点和账号隔离。设置沿用现有字段合并与快照；日志记录状态和耗时，清理限定在应用自有目录。[应用数据路径](../src/EhViewerForPc.Core/Storage/AppPaths.cs#L10) · [设置快照](../src/EhViewerForPc/Services/AppServices.cs#L116) · [在线缓存作用域](../src/EhViewerForPc.Core/Imaging/GalleryImageStore.cs#L117)
5. **验证实际发布物。** 主程序继续走 Windows x64 NativeAOT，协议和持久化 JSON 使用源生成序列化。MSIX 当前递归收集发布产物，再按文件名注入，目录层级会被展平。若随包携带多层依赖的 worker，需保留相对路径并安装实包验证。可选包放在应用数据目录同样需验证 MSIX 下的装载。测试覆盖 Win10 和 Win11，并核对是否满足 MSIX 当前声明的最低 Windows 10 build 17763。[项目 AOT 配置](../src/EhViewerForPc/EhViewerForPc.csproj#L15) · [MSIX 注入](../packaging/EhViewerForPc.Msix/EhViewerForPc.Msix.wapproj#L131) · [MSIX 系统基线](../packaging/EhViewerForPc.Msix/Package.appxmanifest#L28)

## 实施与验收

| 阶段 | 交付 | 建议验收 |
| --- | --- | --- |
| 1. 模型对照 | 工具输出分区、原文和译文 | 选约 24 页自制或获授权图片，含纵排、低清、拟声词、长条、多栏。标注约 100 个对白区块，统计气泡漏检、字符错误及顺序错误。另用约 30 段相同敏感对白复核各模型的拒译、遗漏、淡化和增写。用不含 OCR 错误的标注原文复测疑难句，定位问题所在。 |
| 2. 阅读器首版 | 按钮、编号、可复制双语结果 | 已安装模型后，实际断网翻译本地页和已缓存在线页，翻译端出站请求为零。快速翻页或离开阅读器时至少取消 20 次，旧结果不会发布到新页，退出后无残留进程。源文件路径、大小和 mtime 的前后快照一致。 |
| 3. 图内叠层 | 原图内显示编号或译文，可选停稳后自动翻译 | 测单页缩放、纵横连续、高 DPI、深浅色和窄窗口。记录冷启动、连续翻译 P50/P95、首图时间和进程峰值内存，以目标机器基线确定延迟和内存门槛。 |
| 4. 清字与嵌字 | 按需求提供预览及独立输出 | 验证遮盖、非白底、字体字形和换行。由用户显式触发，输出写入应用自有目录。 |

验证使用 `.qa/` 中的合成图和固定在线缓存夹具，覆盖缺损图、模型包缺失、后端超时、翻页和退出。用全新目录发布并实际启动 NativeAOT，再验证已安装的 MSIX。功能落地时同步项目需求、双语 README 和变更记录。[UI 隔离入口](../src/EhViewerForPc/App.axaml.cs#L96) · [源库快照](../src/EhViewerForPc/Services/SelfTestService.cs#L342) · [项目验证命令](../README.md#-测试与验证)

本文基于项目源码与上游资料。当前缺少目标设备规格，模型推理、端到端兼容性、实机性能、NativeAOT 和 MSIX 运行均待验证。
