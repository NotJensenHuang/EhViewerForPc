# 本地 WebP 阅读回归

2026-11-23，Windows 11 x64。本次使用隔离应用状态、回环站点配置和合成图库。原报告中的八页作品使用保留原格式的只读隔离副本，页面与元数据的敏感内容保留在已忽略的 `.qa/`。

## 故障复现

从旧版 NativeAOT 的「本地库」点击一部完整八页 WebP 作品卡片上的「阅读」。库卡片的封面和八页计数正常。阅读器显示 `1 / 8` 和「无法加载」「请检查网络后重试」，解码日志记录 `ObjectDisposedException: Cannot access a closed file`。从详情或版本打开该合成作品，同样记录异常。真正少一页的合成作品在库中显示 `7/8 页`。

本地阅读新增的翻译图片校验会在解码后读取文件流的元数据。Skia 的 WebP 解码器可能提前释放包装的输入流，校验因读取已关闭的流失败。修复后，Skia 仍可释放包装，底层文件流由调用方保留并在读取结束后释放。

上一轮原始格式覆盖存在空缺。真实翻译界面验证使用了整理后的独立 PNG，`--reader-regression` 使用合成样本并通过诊断页面打开阅读器。此次复现覆盖普通本地库里的卡片、详情和版本交互及原始 WebP 页。

## 交付产物实测

| 样本与入口 | 观察结果 |
| --- | --- |
| 原报告作品隔离副本，本地库卡片「阅读」 | 逐页点击「下一页」，八页均渲染。相邻页采样画布中变化像素占 38.3%–40.1%。解码失败日志为零。 |
| 合成八页 WebP，本地库卡片「阅读」 | 单页的第一页和第二页均渲染，翻页后画布变化。连续和横向均渲染 WebP。 |
| 合成八页 WebP，详情「开始阅读」及版本「用此版本阅读」 | 两个入口均渲染图片。版本切换后渲染另一副本中对应的页面。 |
| 合成 PNG、JPEG 和真缺页对照 | PNG 和 JPEG 首图可读。实际缺失第 2 页时显示「第 2 页缺失」。 |
| 浅色 920 DIP 窗口，模拟已登录状态 | 本地 WebP 前两页均渲染，使用键盘激活「下一页」后画布随页翻动。 |

桌面验证运行从本次交付 ZIP 解压的原样 Windows x64 NativeAOT 程序。真实取样副本和应用使用的副本分别核对了前后路径、大小、修改时间与 SHA-256。测试启动时检查单实例锁与同一会话内的应用进程。已安装的应用与用户数据目录未参与桌面验证。

新增的八页 WebP 自动回归在修复前失败，修复后通过。全量 UI 测试为 167/169，两项既有重试断言在前一轮修复基线也可复现，详见[翻译实测记录](本地漫画翻译实测-2026-11-23.md#阅读器验证)。
