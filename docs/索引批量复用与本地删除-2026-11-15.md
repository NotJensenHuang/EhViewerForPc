# 索引批量复用、完成下载分流与本地副本删除（2026-11-15）

本轮先处理索引更新，再落实新增的下载列表过滤与本地删除需求。「继续下载」触发全库扫描的反馈尚未建立确定复现，本报告不把它列为已修复。此前的小规模提交次数验证见[上一份记录](托盘注册与增量更新修复-2026-11-15.md)。

## 索引诊断与实现

截图显示总量 442,531，已处理 384,412，复用 384,340，新提取 0。只读检查任务后发现，恢复过程会重试原先失败的页；已处理数增长不等于对所有旧页重新提取。抽样中既有 22 字节的非图片文件，也有能解析 JPEG 尺寸但无法完整解码的文件，单页失败解码约 5–25 ms。

旧清单查询使用 `(source_id,stable_id,page)` 主键，缺项查询为几十微秒，排除了全表扫描假设。两万页隔离元数据基线约 2.31 秒，同期 2,028 页真实路径样本约 0.491 秒；当前空闲回放没有复现固定 1 秒 / 页，不能直接断言所有时间消耗都来自同一原因。

已经确认并移除的成本是：未变化页原先仍逐页经过旧 / 断点清单查找、源路径和文件属性核对、worker 调度及逐页结果提交；失败页也计入特征小批，每 10 页就刷盘。上一版仅放大元数据提交批次，没有消除上述路径。

`LocalImageSearchService.Reuse.cs` 现在按最多 4096 个待办候选一窗口，在连接私有内存表中匹配旧清单，只读旧 SQLite 文件，不逐页访问原图或进入 worker。匹配来源、作品副本身份、页号、首选路径、大小与 mtime，清单与完成标记在同一事务中提交。取消保留已提交窗口，写入失败回滚，不新增持久化 schema 或索引格式。

只有新增、变更、失败以及需要尝试其他候选的页进入原提取链。新描述子仍受原小批内存上限约束，失败及其他纯元数据最多 1024 条提交；进度显示「复用 / 新提取 / 失败」。发布前仍按目录核对源文件变化，目录枚举自带的属性用于排除链接页；没有取消源文件变更检测。完全无变化的快捷判断复用本轮新枚举计划的安全属性，只比较完整签名，不再为每页重复访问相同源目录属性。

## 下载与本地删除

`DownloadsViewModel` 在初始化、队列同步和迟到进度三处过滤 `Completed`，完成任务只在「已完成」归档展示。仍保留完成回调对本地库的增量登记，不修改下载队列的持久化兼容性。

卡片右键「删除此副本…」和版本列表删除按钮共用 `LocalCopyDeletionView`：显示可复制的完整路径、范围说明与「移入回收站 / 取消」行内确认。未确认不调用删除服务，操作中禁用重复确认，失败保留原对象和重试入口。暂不新增编辑界面。

`AppServices` 捕获设置快照，先停止并等待本地扫描 / 版本检测收尾。`DownloadManager` 对相关目录设置写入守卫，取消普通下载，等待在途任务与本页重下载关闭文件；活跃资源保留原下载对象与实际 Task，即使用户已从队列移除任务，也等待取消后的收尾，再调用平台回收；期间拒绝新的补页、继续与重下载，迁移 / 归档传输与删除互斥。退出等待包含回收与缓存收尾。完成后移除相关任务、归档、扫描缓存与本地副本状态，不触发全库扫描，其他版本、作品级收藏和阅读进度保留。删除最后一个副本后，本地库和版本页显示正确的空状态。

回收使用 Windows `IFileOperation` 的 `FOFX_RECYCLEONDELETE`，独立 STA 线程与静态 P/Invoke / vtable 调用兼容 NativeAOT，失败没有递归永久删除兜底。[Windows 官方标志说明](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)。数据源根目录、包含应用数据或其他数据源的目录不能作为删除目标，尾分隔符也不会绕过保护。
