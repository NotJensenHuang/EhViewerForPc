# 漫画竖排分组复现与修复

## 同页复现

用生产 C# OCR 源码、真实 ONNX 与同一张 565×799 本地原图复现。原图与逐字输出仅存于本机忽略目录，报告记录位置、ID 和误差。旧分组从右至左先合并原始识别 ID 3、2，把 ID 1 留作另一条翻译请求。两套权重都产生相同的分割。左列起点较中列高约 21 像素，超过原算法按较窄列宽计算的约 11 像素上限。

修复在旧的宽度、重叠、间距与接缝检查后，对有限错位补查封闭的明亮纸底。两列都要落在同一连通域并达到覆盖门槛。边界开口或超过 96,000 像素的搜索区域均被拒绝。原有对齐列规则仍覆盖常规整齐对话及较暗气泡。未加入固定词典修正，检测、首次识别、接受和待核对的记录照常保留。

真实同气泡改为一条翻译输入，组成 ID 为 3、2、1。v5 源文字联合框为 (182,63,62,123)。闭合轮廓内测得横排矩形 (170,77,76,96)，宽度增加约 23%。定位时先排除能从轮廓外到达的像素，再允许原字范围内封闭的浅色区域孔洞。排版与原字遮盖分别使用各自几何。合成回归覆盖闭合泡合并、分隔线保留两组、开口不放宽合并和相邻气泡外文字独立。 隔离 C# 探针三例通过，日志为 `.qa/ocr-seam-20261127/geometry-fixtures.txt`。另复跑既有 20 合成页、300 标注区，整体 OCR、检测和每类计分均与旧统计相同。

## 候选在同一气泡上的表现

| 模型 | 输入 | 逐字编辑 | 位置与顺序 |
|---|---|---:|---|
| PP-OCRv5 | 整张 565×799 页，C# ORT CPU | 5 / 17 | 三列均检测到。新分组按右到左合为一组 |
| PP-OCRv6 Manga FP32 | 整张同页，C# ORT CPU | 0 / 17 | 三列均检测到。新分组相同，页下另接纳两个大框，各输出三个字，暂无真值验证 |
| Baberu v1.2 INT4 / INT8 | 同页中直接裁下的完整气泡，ORT CPU | 7 / 17 | 保留右到左顺序。编辑距离包括把省略号输出为独立点号和一个小假名替换 |

编辑距离按照该气泡人工转写、保留原始标点计算。裁剪识别器使用了已知气泡位置，不能用于比较整页检测召回。单页不能支持默认 OCR 换型。既有 300 区的跨类型对照、下载与模型接口见 [OCR 模型评估](OCR_MODEL_EVALUATION.md)。

## 复现命令

先把授权的本地原图放到 `.qa/ocr-seam-20261127/input/page.png`。指定本机已校验的 v5 模型目录、应用所附的 `manga-native` 和可选的候选模型目录。这些命令只调用本地推理。

```powershell
$work = ".qa/ocr-seam-20261127"
$tools = "tools/translation/ocr-benchmark"
dotnet build "$tools/OcrBenchmark.csproj" --artifacts-path "$work/build"
$bench = "$work/build/bin/OcrBenchmark/debug/OcrBenchmark.dll"
dotnet $bench $native $baseline cpu "$work/input" > "$work/v5-after.jsonl"
dotnet $bench $native $ppocrV6Fp32 cpu "$work/input" > "$work/v6-after.jsonl"
python "$tools/measure_crops.py" baberu $baberu "$work/crop" > "$work/baberu-bubble.jsonl"
```

Baberu 的 `crop` 目录使用真实气泡裁剪，原图对应左上 (172,55)、右下 (250,190)。合并前后记录位于 `.qa/ocr-seam-20261127/v5-before.jsonl`、`v5-after.jsonl`、`v6-before.jsonl` 与 `v6-after.jsonl`。检查结果中的 `Regions.SourceRegionIds`、`BubbleInterior` 以及 `RawDetections` 与 `Observations`。
