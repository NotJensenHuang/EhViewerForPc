# 索引 CPU 并行、批量写入与 SIMD（2026-11-14）

本次落实[原加速方案](以图搜图索引加速方案-2026-11-13.md)中的有界 CPU 提取、批量写入、无变化快速返回和像素 SIMD。用户明确排除 GPU，本次没有引入 GPU 算法或运行库。共享存储与旧缓存迁移仍遵循[存储与恢复设计](索引共享存储与断点恢复-2026-11-13.md)。

## 执行与所有权

- 应用默认按 `Environment.ProcessorCount / 2` 选择 1–4 个提取 worker，执行选项允许验证时指定 1–6 个。每个 worker 独占提取器与只读特征缓存连接；SQLite 写入始终由单一消费方负责。
- `OrderedImagePipeline` 的两个 Channel 有界，另有 `2 × worker` admission 窗口限制乱序重排。最慢的首项不会导致后续结果无限堆积；消费方按原输入顺序分配内容 / 向量 ID，训练与索引保持确定性。
- 默认像素工作区估算配额为 128 MiB，且不超过共享图像预算的一半；队列、批写及连接另预留 `16 + 2 × worker` MiB，整体向 `ImageMemoryBudget` 申请。申请不足时在后台可取消地等待。头部解析、解码、规范化和 ORB 都在工作区配额内，各租约在 worker 返回结果前归还。
- 估算覆盖输入编码副本、RGBA / 灰度、金字塔、池化横向缓冲桶和角点集合。它是活动工作区估算额度，不能等同进程 RSS；托管 GC / ArrayPool 保留、SQLite 页缓存、整个页清单和应用其他状态另有开销，进程峰值需实测。
- 生产者使用自己的只读清单连接和预编译查询；消费方复用后端连接、插入语句与清单事务。来源页只读，写入前再次核对实际大小 / mtime，损坏候选可回退或计为失败，不中断其余有效页。
- 取消、失败、页面离开与退出仍由应用服务管理。取消后先停止并等待所有生产者 / worker，再提交已按序消费的健康批次；失败写入会回滚当前批，随后保存可恢复任务。任务不依赖 UI continuation 收尾。

## 批次检查点与兼容性

默认每 10 页提交一次，共享描述子 → 后端引用 → 清单依次落盘；最后不足一批、正常取消也会提交已消费部分。崩溃从最近提交的批次恢复，当前未提交的最多 9 个已消费页及在途结果可能重算；已提交页面不重算。进度回调在对应批次提交后发布，保留原第 10 页强制退出验证入口。

`ImageDatabase.ImportWriter` 复用连接 / 预编译语句，未提交或失败的批次在释放时回滚。独立 Host 的目录导入也使用相同有界管线，支持 `add --workers 1..6 --batch-size 1..10`。归档输入与后端 / 报告输出也校验分离，并拒绝经过链接的源路径，避免误覆盖原始 Tar。Tar 保留单编码 payload 限制及保守画布配额，避免把大归档页预读到内存；dHash 的近似去重图仍逐项提交，维持既有去重语义。

无变化更新核对完整清单与候选优先级后保留现有发布指针，跳过快照复制、提取、训练和合并。缺失 / 新增候选、删除、源文件签名变化或未完成任务都会进入正常更新路径。

## SIMD

灰度转换与 7 tap 两遍高斯模糊使用 double SIMD，并保留原来的乘加顺序、float 横向中间值、alpha 白底合成与舍入规则；没有使用 FMA 改变舍入。高斯横向缓冲按同步调用独占租借，`finally` 归还；返回像素为独占数组。

JIT 在支持时使用 AVX2；默认 x64 AOT 使用 SSE2，不支持时走标量。没有提高发布目标的 CPU 指令集要求。实际 AOT 测量曾发现仅写 AVX2 分支会在默认发布中被裁掉，因此补充 SSE2 并在原生运行报告中记录实际内核。NativeAOT 以目标指令集生成代码的约束见 [.NET 官方说明](https://github.com/dotnet/runtime/blob/main/src/coreclr/nativeaot/docs/optimizing.md)；JIT 诊断开关不会改变已生成的 AOT 代码，见 [SIMD 文档](https://learn.microsoft.com/dotnet/standard/simd)。

正常页走向量化，其他 EXIF 方向沿用原标量坐标映射；宽度尾部及边缘反射仍有标量处理。归一化 / 提取配置身份与存储格式不变。缩放、FAST、训练和分桶算法未替换。

## 验证与性能边界

所有测试均在后台、独立 `.qa/index-cpu-20261113/` 数据目录运行，未操作用户桌面或真实图库，未改写 J 盘缓存。宿主为 i5-13600KF，子进程设置 `DOTNET_PROCESSOR_COUNT=2`；性能子进程优先级为 BelowNormal。这个环境变量调整运行时 CPU 视图，不是硬性 CPU 亲和性限制；显式 4 / 6 worker 测试仍可并行占用相应数量的线程。

基准为每轮新生成的 16 个合成 PNG（320 × 448，四页为 320 × 896），3 个样本，新建索引后进行无变化更新。源文件刚写入，属于温缓存；不代表冷盘或 24 万页真实库。比较旧提交 `6eb5daf` 与全新 AOT 构建；每轮验证源路径 / 大小 / mtime 不变。
