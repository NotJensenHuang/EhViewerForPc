# 下载增量刷新、速度与批量补页

日期：2026-11-14。基线提交：`79beed8`。Windows x64、.NET SDK 11.0.100、Avalonia 12.1.6 / FluentAvaloniaUI 3.0.2。本记录补充前一版原路径补页实现，未改变索引格式或 GPU 算法。

## 已确认的问题与修复

旧的 `ImportDownloadAsync` 虽只扫描一个目录，却随后对整库执行 `ApplyGalleries`，替换可见列表，并对所有卡片重新生成封面请求。离屏回归的旧实现记录为「单页更新替换列表 1 次」，证据为 `.qa/download-live-20261114/refresh-red.log`。

修复将受影响作品的副本单独重组，保留原卡片实例和顺序；可见集合保持 `ObservableCollection`，只在新增作品或失去筛选资格时增删。显式刷新 / 排序再完整重排，下载进度不移动已有卡片。相同目录和封面路径保留请求；更换默认副本或封面变化仍更新封面。逐页扫描及页数核对移出 UI 线程，不在每次更新时重复保存相同数据源设置。

最初只检查实例和最终数值会漏掉故障：`Move` 会触发 ItemsRepeater 清空数据上下文，即使控件实例未卸载，进度也会发生 `0.6 → 0 → 0.8`。`ring-value-diagnostic.log` 记录完整事件顺序；改为保留已有位置后，`ring-value-green.log` 与 `ring-insert-green.log` 验证全过程不回退，且新任务入库不重置其他环。

测试覆盖原默认副本补页、其他副本补页后成为默认版本，以及本应触发最近下载排序变化的情况，核对列表引用、卡片 / 进度环引用、数值单调、无变化封面与其他作品零属性通知。已安装库的数值动画使用上一数值；本次保留控件与动画状态，没有替换原生控件或自绘进度环。未用真实 Win32 合成器测量动画帧连续性。

## 当前速度

- `GalleryImageStore` 的图片接收进度由每页独占观察器转换为字节增量，累计到任务自己的计量器；并行页面相加，重复累计值不重复计入，Resolving / Decoding 与缓存命中不计入。
- 每个活动任务独占 500 ms 采样循环，使用单调时钟和五个固定采样点计算约两秒滑动平均。下载行及本地卡片显示速度，下载页状态栏汇总。
- 暂停、排队、完成和失败的可见速度为零；旧任务释放采样循环后才释放运行槽，避免恢复时收到旧计量器的迟到更新。采样异常被观察、记录，不遗留后台 Task。
- `BytesPerSecond` 为运行时 `[JsonIgnore]` 字段，不修改队列格式或新增持久化根类型。

真实流式 HTTP fixture 在页面尚未完成时验证速度已大于零，随后让输入停顿并验证归零，再覆盖暂停、立即恢复和完成。第二个副本通过已有缓存补页，验证没有新的图片 HTTP 请求及虚假网速。计量器另用受控单调时钟检查重复进度、并行增量和窗口衰减；不声称网络带宽提升。

## 一键补页与版本检测

「补齐缺页」处理当前筛选列表中全部版本，按原目录去重。已有运行 / 等待任务不重复添加；暂停、失败或已完成后又缺页的任务复用原实例。缺失 GID / token、路径不可用等错误逐项展示。Core 在锁外校验目录，在锁内准备有效任务并统一保存一次；保存失败或提交前取消回滚此次准备，保留原任务和已落盘页。测试验证单次变更通知、重复批次不写被锁定的队列文件，以及混合新旧任务的回滚。

详情页新增已有版本管理页的入口。打开版本页时逐一后台读取原目录，可检测所有版本或单独重检；分别显示缺页范围、0 字节数量和预期页数。预期页数来自本地元数据或已有作品记录，不额外联网核实。没有总页数时只能检查页号内部空洞，不宣称尾部完整；离线或不可读副本单独失败，其他版本成功更新不会清除该失败信息。检测复用现有格式解析与扫描器，不写源文件、不执行整图解码或内容哈希校验。

## 验证

全部数据、日志、截图、探针源码和发布产物在已忽略的 `.qa/download-live-20261114/`，部分测试复用 `.qa/progress-repair-20261114/` 的合成 fixture。真实资料库与账号未参与；全程 BelowNormal / `DOTNET_PROCESSOR_COUNT=2`，所有图形运行使用 Headless + Skia，不创建真实桌面窗口、不操作键鼠。

- 最终回归：Core 160、后端 76（GPU 用例开启）、Headless UI 76，共 312 项通过；对应三个工程的 `.log` / `.trx`。进度连续性断言同时覆盖默认副本变化、新任务入库与全过程数值不回退。
- 最终全新 AOT：`app-aot-final`、`ui-aot-final` 发布并实际运行成功。`app-probe-final.json` 12 项通过；`native-ui-final.stdout.log` 包含新编译绑定、批量去重、详情导航、不同版本的缺页结果、现有顺序保持与进度数值单调验证，亦回归上一版索引 / 阅读 / 书签流程。使用带无关作品的场景确保旧代码确实会触发排序移动；仅检查控件实例和最终值的早期构建不能作为本次最终修复证据。
- 复验时发现旧 `ParallelTrainingObservesCancellation` 依赖线程池 `CancelAfter(10 ms)`；在受限双逻辑处理器环境下，训练结束时取消标志仍为 false（`cancellation-timer-diagnostic.log`）。仅将该测试改为独立线程触发取消并等待线程结束，不改训练算法；旧失败日志保留为 `backend-timer-failure.*`。
- 新增用例包含进度环 / 列表保留、未选中副本更新、批量去重与部分失败、队列保存失败回滚、提交前取消、单页在途速度、缓存命中、逐版本缺页与离线失败隔离，以及详情导航。
- 离屏截图覆盖库、下载、详情和版本页的深浅主题，920 / 740 / 640 DIP 及 540 × 420 DIP；首轮检查后把版本检测结果独立成行，避免与修改时间粘连。检测器输出 `ui-detect.json` 为 `[]`。
