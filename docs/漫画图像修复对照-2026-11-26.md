# 漫画图像修复对照

现有 `MangaTranslationOverlay.Draw` 在阅读器叠层内用白矩形遮盖原文，然后居中画译文。识别区域的几何框能定位文字，形成字形掩膜仍需从像素或检测模型输出中提取。以下实验固定精确的字形掩膜，单独测图像修复本身。

## 对照结果

Windows 工作区，Python 3.11.8，OpenCV 4.10.0 CPU。两张 400 × 240 灰度合成图。第一张为白色气泡，第二张为灰阶渐变、斜线和曲线背景。两张图在同一位置叠加 SFX，字形掩膜扩张一像素后共 3,809 像素。三个候选使用同一输入。矩形覆盖取掩膜的外接矩形。Telea 和 Navier–Stokes 取相同 3 像素修复半径。

| 方法 | 白气泡掩膜内 MAE | 线稿掩膜内 MAE | 线稿掩膜外变化像素 | 线稿全页 MAE |
| --- | ---: | ---: | ---: | ---: |
| 带原文字样 | 159.341 | 102.297 | 0 | 4.059 |
| 白色矩形 | 0 | 88.070 | 2,974 | 6.083 |
| Telea | 0 | 16.896 | 0 | 0.670 |
| Navier–Stokes | 0 | 17.054 | 0 | 0.677 |

```powershell
python tools/translation/Measure-Redraw.py .qa/translation-redraw-run
```

本轮输出位于 `.qa/translation-candidates-20261126/redraw-v1/`，含干净底图、带文字图、掩膜、三种结果和报告。每次使用一个尚未创建的输出目录。误差按 0–255 灰度算，低值表示更接近已知底图。统计范围不含可读性、气泡内排版或文字检测的误差。

## 候选与验收边界

OpenCV 的两种传统算法适合作为可靠小掩膜的 CPU 对照。LaMa 使用频域卷积处理遮挡，仍需要相同的掩膜输入；Manga Image Translator 提供 LaMa Large、LaMa MPE 等可选修复后端。当前未测两者的真实漫画效果、许可证组合与 RTX 8 GB 峰值。先固定权重及推理配置，再按同一页面、同一掩膜复测并与 OpenCV 对照。[OpenCV 修复接口](https://docs.opencv.org/4.x/d7/d8b/group__photo__inpaint.html) · [LaMa](https://github.com/advimman/lama) · [Manga Image Translator](https://github.com/zyddnys/manga-image-translator)

本轮没有将真值字形掩膜算法推入阅读器。真实掩膜一旦混入线稿，算法只在掩膜内改像素也可能错误擦除轮廓。进入生产前还需覆盖细线穿字、网点、深底反白、彩色边缘和艺术字，分别记录真实掩膜损伤率、残字和字体缺失。版面验收包括窄竖泡、异体字、换行、旋转、译文溢出及 SFX，和擦除评测分别记录。
