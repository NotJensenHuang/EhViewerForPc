# 本地漫画翻译原生后端

2026-11-24，Windows 11 x64。阅读器在用户点击「翻译本页」时启动当前应用的无窗 C# 工作进程。工作进程使用应用随附的 ONNX Runtime DirectML 和 llama.cpp Vulkan 库，完成后通过标准输出返回一页 UTF‑8 JSON。它在应用状态、单实例和 Avalonia 初始化之前进入独立分支，工作过程没有 HTTP 服务或推理请求。设置中只有主动准备模型会访问模型下载源。

旧版安装显示「正在准备本地翻译运行时」时，现场已经解包 Python，随后长时间停留在 `llama.zip` 下载阶段。现场记录无法判定具体的代理、服务端或读取原因。新版发行包已包含 GPU 库，应用内只准备模型。模型连接与读取停滞按超时处理，设置会显示当前资源与重试原因。

## 使用和兼容性

- 使用 Windows x64 发行包的完整目录结构。GPU 与驱动需要支持 DirectML 和 Vulkan。程序在识别时检查模型实际执行的 DirectML 节点，Hy-MT2 加载时检查 Vulkan 设备和层卸载状态。
- 在「设置 → 界面与阅读 → 漫画翻译」保存本机模型目录并点击「下载并准备模型」。首次全缺失时需要四项文件，共 1,154,605,342 字节。应用按固定 SHA‑256 校验，显示连接、具体文件与传输字节、校验和重试，可取消后保留已校验完整的文件。
- 默认 `manga-translation/backend/models` 与旧版相同，自定义模型目录继续有效。旧的 `EHVIEWER_MANGA_TRANSLATION_BACKEND` 在未指定目录时可提供 `models` 子目录。已有匹配权重可重新校验复用，旧运行时文件保留在原处。
- 本地页和已加载的静态在线页复用原有页面身份、只读图像流与定向快照。识别的同气泡竖列在通过对齐和边界判据后共同送译。返回的像素矩形驱动图上覆字，原样返回或无文字的区块保持原画面。取消、翻页或退出时等待工作进程清理，临时快照放在独立作业目录。

早期 Python / llama-server 版的桌面、GPU 实测与样页记录独立保留。[设置、下载与图上译文实测](漫画翻译设置与覆字验证-2026-11-24.md) · [真实页抽取记录](本地漫画翻译实测-2026-11-23.md)

## 构建原生资产与发布

源构建从以下固定版本的官方归档提取 Windows x64 DLL 和许可材料。PowerShell 7 脚本验证整个归档 SHA‑256。DirectML 文件从发布归档按 ZIP 提取，构建和运行都无需安装 Python。CRT 来源是具备再分发许可的 Visual Studio 2026 `Microsoft.VC145.CRT` x64 目录，脚本可通过 `vswhere` 定位，也可传 `-VcRedistDirectory`。

- ONNX Runtime DirectML 1.23.0 的 NuGet 原生构件与 C API 头。[Microsoft NuGet 归档](https://api.nuget.org/v3-flatcontainer/microsoft.ml.onnxruntime.directml/1.23.0/microsoft.ml.onnxruntime.directml.1.23.0.nupkg)
- DirectML 1.15.4 DLL，取自 ONNX Runtime DirectML 1.24.4 官方 Windows x64 归档。[官方发布归档](https://files.pythonhosted.org/packages/be/90/99566dc6398028e7691a5b12720fd85f757a0901818b84599d28abb3f085/onnxruntime_directml-1.24.4-cp311-cp311-win_amd64.whl)
- llama.cpp b12650 Vulkan x64 库。[上游 Windows x64 Vulkan 归档](https://github.com/ggml-org/llama.cpp/releases/download/b12650/llama-b12650-bin-win-vulkan-x64.zip)

```powershell
pwsh -NoProfile -File tools/translation/Prepare-NativeAssets.ps1 `
  -OrtPackage .\sources\microsoft.ml.onnxruntime.directml.1.23.0.nupkg `
  -DirectMlArchive .\sources\onnxruntime_directml-1.24.4-cp311-cp311-win_amd64.whl `
  -LlamaArchive .\sources\llama-b12650-bin-win-vulkan-x64.zip

dotnet publish src/EhViewerForPc -c Release -r win-x64 -p:PublishAot=true -o artifacts/win-x64-aot
```

默认原生资产输出为 `artifacts/translation-native`。完整发布目录应包含 `manga-native/ort/` 与 `manga-native/gguf/`，两个目录各自保留依赖库与许可文件。模型资源由设置按需准备。MSIX 收集应用原生资产时保留相对目录名。

本次 Windows x64 NativeAOT 便携包为 `artifacts/EhViewerForPc-win-x64-native-manga-translation-20261124.zip`，共 77,144,752 字节，SHA‑256 为 `21DDDCF59807E4D47226A89B351223C6B97764043B199237D0EA958055345CB3`。核对了 ZIP 内 exe 与候选 exe 的哈希，以及 23 项原生资产的逐项哈希。完整清单见 `.qa/manga-native-delivery-20261124/delivery.json`。

## 验证范围

- 已在无窗单线程 CPU 探针上用随包 ONNX Runtime 实际加载和释放两种正式模型，各执行两次。`det.onnx` 的 32 × 32 输入产生 `[1,1,32,32]`，`rec.onnx` 的 64 × 48 输入产生 `[1,8,18385]`。探针只启用 CPU，用于覆盖 C API 的加载、张量格式、读取和资源释放。
- 两张匿名日文竖列裁片各实测编辑距离 1。回放该页的 15 个识别框得到 13 个区块，其中同气泡的三列合为一个翻译单元。另在无窗 CPU 模式加载已固定 Hy-MT2 模型词表和对话模板，核对 b12650 的三个 C ABI 布局。裁片结果见 `.qa/translation-stall-diagnosis-20261124/native-ocr-report.json`。
- 无窗关联系统测试 17/17 通过，覆盖模型资源下载状态、等待下载超时、取消与重试、空白页 IPC、坏 JSON、进程退出和图上几何。记录见 `.qa/translation-native-ocr-probe/manga-translation-tests.xml`。
- Debug 托管和全新 Windows x64 NativeAOT 各运行三项无窗工作进程错误用例。无输入、非随包运行时、不可解码 PNG 分别返回 4、3、4，标准输出和标准错误为空，指定的隔离应用目录无写入。记录见 `.qa/manga-native-delivery-20261124/worker-native.json`。
- 在获准进行 GPU 验证后，使用 GeForce RTX 5070 Ti 对同一个发行版 exe 做两次独立整页推理。两页均返回 `DmlExecutionProvider` 与 `Vulkan0`，并由工作进程核对实际 GPU 层卸载。原创样页的 5 个区块都有译文。与此前输入 SHA‑256 相同的隔离真实页识别出 11 个区块，其中两个含假名的区块都生成简中译文，包括由左下三竖列合成的 `111 × 129` 像素识别区块。另九处识别为英数或符号，模型原样返回，因而保留原画面。未测其他显卡、新机或 Windows 10。

### 解压发行包后的界面实测

- 自选本机模型目录预置三种配套资源，使用最终 ZIP 解压后的应用从设置页补齐 `det.onnx`。取消后重试成功，从 ModelScope 经 HTTPS 下载 4,819,576 字节，实测 3.51 秒。界面显示连接、当前文件、传输字节和 `Hy-MT2-1.8B-Q4_K_M.gguf` 校验。四项模型 SHA‑256 全匹配，未留下 `.part` 或运行时下载目录。记录见 `.qa/native-manga-foreground/delivered-desktop/settings-progress-summary.json`。
- 从本地库阅读已隔离的真实日文页，点击「翻译本页」后图上显示两个译文区，实测 13.52 秒。覆字后画布有 3,456 像素变化，恢复原图后差异为零，放大后仍可见覆字。源页路径、大小、修改时间和哈希一致。记录见 `.qa/native-manga-foreground/delivered-desktop/native-desktop-summary.json`。
- 推理期间按约 100 ms 采样只观察到同名应用工作进程，未采到工作进程的 TCP 连接或监听。工作进程退出后页快照目录为空，随后关闭应用也未留下暂存输入。记录见 `.qa/native-manga-foreground/delivered-desktop/native-close-summary.json`。

### 样页译文对照

- 原创样页中的「また会えてうれしい。」实际输出「能再次见面真高兴。」。真实页右侧称谓保留，早期 OCR 混入的拉丁字母已消失。左侧合并区虽有译文，原句的主要动作和程度仍有遗漏。
- 使用同一模型与固定随机种子在 `Vulkan0` 对照三段输入，实际卸载 33 层。以实际 OCR 拼句送译时，译文遗漏强调和表示「紧」的意思。人工等义整理后这两处得到保留，动作仍需结合上下文。中性无歧义对照句保留了动作。此结论仅覆盖三段输入。记录见 `.qa/translation-stall-diagnosis-20261124/fixed-seed-compare/semantic-evidence.json`。
