# 站点直连与详情封面验证

## 安卓原版

对照上游默认分支 2026-11-19 的提交 `243c39b30facccd74802691ec10e723624103ec5`。

- 页面与图片客户端都使用 `EhHosts`。用户 hosts 优先，其次是内置站点地址、可选 DoH 和系统 DNS。表站与里站的内置地址分别默认开启，DoH 默认关闭。地址会随站点迁移而过期。[地址表与解析顺序](https://github.com/xiaojieonly/Ehviewer_CN_SXJ/blob/243c39b30facccd74802691ec10e723624103ec5/app/src/main/java/com/hippo/ehviewer/client/EhHosts.java)
- 上游的「域名前置」开关默认开启。Android 未检测到 VPN 时，客户端按已连接的远端 IP 建立 TLS，握手时可以省略原站域名的 SNI，HTTP 请求仍使用原域名。[客户端接线](https://github.com/xiaojieonly/Ehviewer_CN_SXJ/blob/243c39b30facccd74802691ec10e723624103ec5/app/src/main/java/com/hippo/ehviewer/EhApplication.java#L431-L469) · [TLS 工厂](https://github.com/xiaojieonly/Ehviewer_CN_SXJ/blob/243c39b30facccd74802691ec10e723624103ec5/app/src/main/java/com/hippo/network/EhSSLSocketFactory.java#L35-L50)
- 上游详情解析从 `#gd1` 子元素的 CSS 背景读取封面 URL。桌面版此前只读取 `img`。从列表进入详情时已有缩略图，粘贴链接进入时没有这个来源，因此会出现标题、元数据完整但封面空白。[详情封面解析](https://github.com/xiaojieonly/Ehviewer_CN_SXJ/blob/243c39b30facccd74802691ec10e723624103ec5/app/src/main/java/com/hippo/ehviewer/client/parser/GalleryDetailParser.java#L179-L186)

## Windows 实现

在「设置 → 网络 → 代理模式」选择「站点直连」并保存。默认值仍是「跟随系统」。每个直连套接字选择具有可用路由的活动物理以太网或 Wi-Fi 接口，指定出站接口并绑定该接口的源地址。没有可用物理路由时连接失败。该模式的作用范围是应用内 HTTP 客户端，外部网页登录沿用浏览器的网络配置。[Winsock 接口选项](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options)

已知站点先使用用户 hosts 或内置候选地址，省略 SNI 时使用系统信任链，并对证书按原始请求域名匹配。握手可以更换地址或使用常规 SNI。请求仍由同一个 HTTP 栈处理，保留 Cookie 作用域、重定向及 Referer。动态 H@H 图床使用正常 SNI。站点解析只收到 Fake-IP 时，直连模式可向阿里公共 DNS 查询真实地址。本机观察到的是配对的 `198.18.0.0/15` 和 `fdfe:dcba:9876::/64`；针对 IPv6 的处理限于已知图库域名出现此组合的情况。

## 本机证据

环境为 Windows x64（构建 26300）、.NET SDK 11.0.100、物理以太网，Clash TUN 在运行。所有站点测试使用空 Cookie 容器或隔离数据目录。没有更改系统路由、系统代理或 Clash 配置。

| 检查 | 结果 |
| --- | --- |
| 普通 SNI 对照 | 绑定同一块物理网卡，在五个上游候选地址上发起 TLS 握手，均被重置。仅禁用 HTTP 代理的对照测试仍取得 TUN Fake-IP。 |
| 省略 SNI 并验证原域名 | E-Hentai 在一个候选地址上返回 200 且页面含画廊链接。ExHentai 在两个候选地址上返回 302，指向论坛登录。 |
| Release Core 的实际内容链路 | 匿名首页 25 项；一个 131 页画廊解析到首批 20 个预览，详情封面下载 34,602 字节，首张 H@H 正文图下载 143,088 字节，两者均通过图片头识别。 |
| ExHentai 访问范围 | 成功连接站点。匿名客户端首页解析到 0 个画廊。授权账号的里站内容与截图所示私人会话未实测。 |
| 最终 Windows x64 NativeAOT 程序 | 在隔离目录运行 `--online-probe`。E-Hentai 返回 25 项，选中的画廊有 128 页，详情封面域名为 `ehgt.org`，缩略图为 22,186 字节，成功解析到 H@H 页图地址；匿名 ExHentai 未返回画廊。两个站点的报告分别为 `.qa/site-direct-20261121/online-EHentai.json` 和 `online-ExHentai.json`。 |
| 链接直达封面回归 | 修复前三个 CSS 封面用例均返回空地址。修复后测试从搜索框打开两站链接，检查目标域名、Referer 和图片控件解码完成状态。六组用例覆盖深浅色与 1240、920、740、640、540 DIP 宽度，最小为 540 × 420 DIP。 |

原始物理网卡握手对照位于 `.qa/clash-direct-physical-20261121/physical-helper.txt`，应用内容链路位于 `.qa/clash-direct-http-20261121/core-physical-dns-final.txt`，Windows SDK x64 的原生结构尺寸及偏移实测位于 `.qa/clash-abi-20261121/layout.txt`。Wi-Fi、纯公网 IPv6 和 Windows 10 未单独上机验证。

Core 测试 224 项及在线 UI 测试 21 项通过，报告位于 `.qa/site-direct-20261121/tests/`。最终 NativeAOT 程序运行 `--ui-audit` 生成 126 张截图，网络设置的深浅色、宽窄窗口场景均无横向溢出。审计另记录横向与沉浸阅读器的 8 项越界，见 `.qa/site-direct-20261121/audit/audit.json`。发布保留 Avalonia / FluentAvalonia 的剪裁与 AOT 告警。

## 复现

在全新输出目录发布程序。给 `--data-dir` 指定独立的 `.qa` 子目录，在其 `settings.json` 写入 `{"network":{"proxyMode":"EhDirect"},"account":{"site":"EHentai"}}`。测试 ExHentai 时用第二个目录，将 `site` 改为 `ExHentai`。匿名 Ex 首页返回空列表时，在线探针会以非零状态退出。

```powershell
dotnet test tests/EhViewerForPc.Core.Tests -c Debug
dotnet test tests/EhViewerForPc.ImageSearch.Ui.Tests -c Debug -p:PublishAot=false --filter FullyQualifiedName~OnlineParityIntegrationTests
dotnet publish src/EhViewerForPc -c Release -r win-x64 -p:PublishAot=true -o .qa/direct-repro/native
.qa/direct-repro/native/EhViewerForPc.exe --online-probe --data-dir .qa/direct-repro/eh --out .qa/direct-repro/eh.json
.qa/direct-repro/native/EhViewerForPc.exe --ui-audit --data-dir .qa/direct-repro/ui-data --out .qa/direct-repro/ui
```

在线探针会检查首页、详情封面域名、列表缩略图和正文图地址。本次实际正文图字节由使用生产 `EhClient` 的独立探针获取，仅在内存中检查图片头。与站点无关的标签库更新不计入直连验证。
