# 漫画竖排气泡分组模型对照

在 565 × 799 的本地样本上，PP-OCRv5 和 v6 都检出了同一个气泡里的三列日语。两者都将列 [3,2] 和 [1] 输出为两个翻译区域。检测保留三列，错误发生在把文字列组成气泡的阶段。更换日文识别器可以改善字符，却不会自行修复区域拆分。

## BubblePop 本地验证

采用作者提交 4d061822eb75994f8d9cc9c610d518654a8e4df0 的 web-demo/assets/model.onnx。资产 3,752,020 字节，SHA-256 为 6a3973677f55b4cac1618714e0565af5f41c9a2158068353abd98e115de4e319。作者发布仓库标注 Apache 2.0。ONNX 是固定 1024 × 768 单通道灰度输入，FP32 接口，作者说明其中的权重经 FP16 舍入。代码按作者的 0.5 掩膜阈值、60 像素实例面积和 0.6 实例置信度提取气泡。[作者源码与许可](https://github.com/letmutex/bubble-pop/tree/4d061822eb75994f8d9cc9c610d518654a8e4df0) · [ONNX 导出方式](https://github.com/letmutex/bubble-pop/blob/4d061822eb75994f8d9cc9c610d518654a8e4df0/export.py)

模型检出 1 个气泡，外接框 (155, 40)–(262, 214)，掩膜面积 14,107 像素，实例置信度 0.9357。以识别框多边形被气泡掩膜覆盖的像素比例判定归属，阈值为 50%。

| 输入文字检测 | 主气泡列的掩膜覆盖 | 匹配后列序 | 合入的气泡外原始检测 |
| --- | --- | --- | --- |
| PP-OCRv5 | 3/3，每列均为 100% | 右→左 [3,2,1] | 0/4 |
| PP-OCRv6 | 3/3，每列均为 100% | 右→左 [3,2,1] | 0/2 |

本机采用 ONNX Runtime 1.19.2 CPU、6 线程，两次启动各推理三次，单图模型运行耗时 24.808–44.856 ms，不含预处理、识别和翻译。结果在 .qa/ocr-layout-20261127/bubblepop-v5.json 与 bubblepop-v6.json。此对照保持 PP-OCR 的原框和文字输入，差别只来自气泡归属与右→左排序。气泡外拟声词进入原有路径，模型没有提供这些字的位置或转写。

从仓库根目录执行，模型下载与本地图片评测是独立的命令。把 $source 与 $baseline 指到相同页及对应的现有 OCR 评测结果。

~~~powershell
$dir = '.qa/ocr-layout'
$null = New-Item -ItemType Directory -Force $dir
curl.exe -fLsS -o "$dir/bubblepop.onnx" 'https://raw.githubusercontent.com/letmutex/bubble-pop/4d061822eb75994f8d9cc9c610d518654a8e4df0/web-demo/assets/model.onnx'
python tools/translation/ocr-benchmark/measure_bubble_layout.py "$dir/bubblepop.onnx" $source $baseline "$dir/result.json"
~~~

当前样本足以说明 BubblePop 值得作为独立的可选分组证据。单页只有一个主要气泡，还需用相邻、重叠、透明及开口气泡验证误并率。应用侧先改善保守的原有分组逻辑，气泡模型优先用于规则产生歧义的页面。跨气泡排序需结合分镜，保持对掩膜外文字的处理。模型对照仅写入本地几何结果，原图保持只读。

## 本地可选分组证据

生产 OCR 工作进程现在可使用 BubblePop 补充气泡归属。可选权重只从选中的模型目录读取，不改变安装器的必需资源。把上方固定发布的 `bubblepop.onnx` 放在 `det.onnx` 所在目录。工作进程首次处理有多个可接受文字框的页面时校验 3,752,020 字节和固定 SHA-256 后加载，缺失、校验失败或 ONNX 推理失败时沿用原有分组。进程每页最多推理一次，使用 CPU，输出内存经池化并在本页用完后归还。复制或移除模型后需要用新的翻译工作进程，重新启动应用即可。已有识别输出会继续记录页内几何和原文字段。

置信度至少 0.8 的气泡实例才用于判断。文字框的 49 个均匀采样点中，至少 37 个须落入同一已确认气泡，且不能有样点落在另一个已确认气泡。不同气泡的判断只否决现有候选合并，未归属列不能把两个已知气泡串成同一链。同气泡的预测不会新增合并条件，仍检查方向、列宽、距离、重叠和接缝。审校记录的 `BubbleInstanceId` 是该页临时实例编号。

最新 1248×1760 授权原图的漏译先修了规则路径。旧算法遇到超过 160,000 像素的固定搜索窗即退回。新算法在预算内取最大搜索窗，仍须检测到同时覆盖两列的闭合纸底。无额外模型时，原来分开的 [3,2] 与 [1] 合成 [3,2,1]，送翻文本保留 18 个字符。该案例与已有两张真实授权页有无 BubblePop 时的正确分组相同。四张大小、邻近和开口变化的合成页均得到两个独立气泡，外部音效保持独立。

另用六张 1130×1598 合成页专测低对比双气泡的错误合并。原规则误并四张，可选模型纠正其中三张。一张实例覆盖不足，仍由原规则处理。原本正确的两张继续保持。真实页样本过少，暂无总体错误合并率结论。三张真实页的模型有无对照、两类合成页及损坏权重回退结果仅在本机 `.qa/ocr-bubble-product-20261127/`。 单轮整页 CPU 源码基准中，三张真实页启用时 757–1490 ms，关闭时 554–1111 ms，包含 OCR、可选模型前后处理和分组，样本过少不作为延迟分位数。大小正确且 SHA 不符的同名文件，在三张真实页上的输出与完全缺失文件逐字段一致。独立探针的 5 个缩放/边界案例和 3 个气泡链案例通过。

```powershell
$work = ".qa/ocr-bubble-product-20261127"
$tools = "tools/translation/ocr-benchmark"
python "$tools/generate_adjacent_bubbles.py" "$work/adjacent"
dotnet build "$tools/OcrBenchmark.csproj" --artifacts-path "$work/build"
$bench = "$work/build/bin/OcrBenchmark/debug/OcrBenchmark.dll"
dotnet $bench $native $modelsWithoutBubblePop cpu "$work/adjacent" > "$work/adjacent-without.jsonl"
dotnet $bench $native $modelsWithBubblePop cpu "$work/adjacent" > "$work/adjacent-with.jsonl"
```

`$native` 指向应用所附的 `manga-native`。两套模型目录使用相同 OCR 权重，仅第二套包含校验通过的 `bubblepop.onnx`。检查 `Regions.SourceRegionIds` 与 `Observations.BubbleInstanceId`。
