## 行为与职责

| 需求 | 实现与状态来源 |
| --- | --- |
| 图片索引构建进度 | 后端 `IndexBuildProgress` 报告特征分配数、分区写入 / 合并数、文件校验字节数。服务保留状态，页面重开后绑定同一后台任务；百分比仅表示当前阶段。 |
| 原路径补页 | `AppServices.ContinueLocalDownloadAsync` 捕获选中副本，交由唯一 `DownloadManager.EnqueueRepair` 入队；卡片、右键、详情与版本行复用此入口。 |
| 阅读方向与输入 | 更多菜单同时显示左右两个原生单选项，仅横向连续模式启用。RTL 只反转页面排列，左键上一页、右键下一页；滚轮物理滚动方向与单页点击区域固定。 |

构建阶段原先只有进入阶段时的一条文本，界面进度条固定为活动指示。新增进度沿真实分配、分段、合并和 SHA-256 读取路径产生，普通更新最多约 10 次 / 秒，阶段切换和完成立即上报。提取页数仍独立保留。没有可靠总量的训练等阶段继续使用活动指示，不制造整体完成率。

已有索引在单次构建内复用首次验证得到的只读索引对象，避免合并前重复完整校验。校验循环支持取消；新文件仍先校验再原子替换，取消不会覆盖旧发布文件。

## 补页与文件边界

按最新用户确认，本地库已解除早期的全局只读限制，允许用户主动编辑、删除；本次只更新约束，不新增编辑 / 删除管理入口。扫描、阅读和索引仍不会自动改动源文件，自检的源快照比较保持有效。

补页任务采用以下边界：

- 路径必须是已存在数据源中的既有副本，不能落入应用数据目录或经过目录联接 / 链接；目录丢失时失败，不创建替代目录。
- 需要 GID 与 token；执行时重新获取画廊页数及完整页面列表，保持原请求限速、画质与失败页处理。
- 使用独立任务键区分同 GID 的不同副本；同一目录重复点击复用任务，暂停后的继续请求在旧写入收尾后执行，不静默丢弃。
- 只新增缺失页，保留已有有效页、原 `.ehviewer`、`.thumb` 等文件；存在同名原文件时报告失败页，不覆盖。临时文件使用独立名称并在取消 / 失败后清理。
- 补页任务不能通过下载队列的“删除文件”操作删除原副本；可以移除任务。此限制针对补页任务，不恢复已撤销的全局只读设计。
- 不修改全局下载根目录，不重新注册原数据源；启用下载完成更新时，仅刷新选中副本所在目录。

索引二进制格式、特征身份与检查点兼容；后端测试比较有 / 无进度入口的完整发布文件字节一致。下载 JSON 只新增可选的 `TaskKey` / `FillMissingOnly` 字段，沿用现有源生成 `DownloadFile` 上下文，旧任务仍使用原 GID 标识。队列保存失败会回滚本次入队状态。
