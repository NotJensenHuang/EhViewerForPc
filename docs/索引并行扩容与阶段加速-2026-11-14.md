# 索引并行扩容与阶段加速（2026-11-14）

本次修订[首次 CPU / SIMD 实现](索引CPU并行与SIMD验证-2026-11-14.md)中的资源策略。用户反馈 CPU 与磁盘仍有余量，本次以真实应用索引服务建立较大页面的可重复反馈回路，未访问或改写用户的图库、J 盘缓存，未引入 GPU。

## 复现与定位

先核对线程上限、工作区等待、顺序提交三个假设。原版 `eeb5ac7` 默认 4 worker、128 MiB 工作区，且该工作区最多只能占阅读器额度的一半。48 张 1200 × 1700 合成 PNG 的单页估算工作区约 45.7 MiB，因此最多只有两页同时解码 / 提取，其余线程等待；中位建库时间约 6.05 秒，平均占用约 1.88 个逻辑核心。该场景写入累计不足 70 ms，优先解除像素配额限制比增大事务批次更有意义。

12 worker 的 barrier 回归先在旧版真实管线上失败（`ArgumentOutOfRangeException`），解除上限后通过。新管线记录实际活动页峰值和配额等待累计时间；对照中，128 MiB 的 4 worker 配置仍只有 2 页同时活动，512 MiB 达到 4 / 8 页，默认 1024 MiB 达到 18 页，确认了资源配额对并行度的影响。

## 资源与并行策略

- 默认提取并行度为逻辑处理器数减 2，限定在 1–32。这里是线程数上限，不是 CPU 亲和性或为桌面硬性保留两个核心。
- 默认像素工作区为每 worker 64 MiB，最低 128 MiB，最高 1024 MiB；同时受 GC 可用内存上限的 1/16 约束。未取得有效内存信息时回退到 128 MiB。[GC 的该属性](https://learn.microsoft.com/en-us/dotnet/api/system.gcmemoryinfo.totalavailablememorybytes)反映 GC 内存上限 / 上次 GC 的信息，不是实时空闲内存，本次没有把它当作实时负载控制器。
- `ImageMemoryBudget` 统一记账，前台位图与后台索引分别限额。阅读器原有 64–1536 MiB 设置不变；索引不再被其一半额度限制，也不会占用前台显示额度。索引另外预留 `16 + 2 × worker` MiB 给连接、排队结果和批写，所有索引租约合计有独立上限（工作区内存容量加最多 80 MiB）。
- 估算配额覆盖活动像素与提取临时数据；GC / ArrayPool 保留、SQLite 页缓存及其他进程状态会使 RSS 与该额度不同。本次没有把工作区配额描述为进程内存硬上限。
- 保留两个有界 Channel 和 `2 × worker` admission 窗口。SQLite 仍单写者、默认 10 页提交；写入顺序、稳定 ID、检查点提交顺序、共享特征存储和源文件只读约束不变。
- 训练的描述子中心分配分段并行，中心位直方图由各并行上下文独占；随机初始化与两级分组的顺序不变，距离合计采用整数。分桶阶段只读共享量化器、按页并行查桶，再按原向量顺序写段。
- HNSW 中心图插入、元数据写入和最终文件合并保留顺序执行。没有宣称全程满核。取消会等待并行任务结束，未发布的批次 / 段沿既有恢复路径处理。
- 独立 Host 的 `add` / `train` / `build` 均支持 `--workers 1..32`，默认同上。Tar 仍保留单编码 payload 约束；本次扩大的是目录提取并行度。

诊断 `PeakParallelPages` 只统计拿到工作区之后的活动页；`MemoryWaitMilliseconds` 是各线程申请工作区的等待时间之和，不能直接当作端到端耗时。进度文本显示本次提取并行度。

## 受控性能对照

环境为 Windows、i5-13600KF（14 核 / 20 线程）、.NET 11.0.100。基准进程为 BelowNormal，未设置 `DOTNET_PROCESSOR_COUNT`，未设亲和性。每项三个样本，各自使用全新数据和索引目录；每轮生成 48 张 1200 × 1700 合成 PNG 后再建库，属于温缓存。计时覆盖真实 `AppServices.ImageSearch.BuildAsync`，不含媒体生成，但包含扫描、提取、训练、分桶、提交和发布。

下表使用 Release 托管程序（JIT），不是 NativeAOT 倍数对照。所有对照在构建与测试结束后串行运行，没有其他本次 QA 工作同时占用 CPU。旧版二进制在修改生产代码前单独发布并保存，未使用新 DLL 覆盖。原始数据在 `.qa/index-throughput-20261114/controlled-*/report.json`，汇总为 `performance-summary.json`。
