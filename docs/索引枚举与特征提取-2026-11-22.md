# 本地以图搜图索引枚举与特征提取（2026-11-22）

基线为 `6fdb930`。Windows x64（10.0.26300）、.NET SDK 11.0.100。使用合成数据，所有索引和日志写入工作区 `.qa/`。H 盘样本只用于目录枚举。各阶段的计时边界与样本如下。

## 枚举和增量更新

- 编号页按八位文件名确定页号，普通图片目录按现有自然排序确定页号，两者沿用相同的候选优先级。索引只需要这些页面和枚举器返回的文件属性。过去每轮还为每个目录打开一次 `.ehviewer`、计算缺页范围和扩展名摘要。索引现在直接取页列表，原库扫描继续生成完整诊断。目录路径逐级检查重解析点，每级读取一次属性，枚举时排除链接文件。
- 初次计划和发布前发现变化的画廊将候选写入连接私有的 SQLite 暂存表，按画廊统一比对、更新页表和候选表。暂存范围为单画廊，持久化事务每 16 个画廊提交。已存在的页保留计划序号，完成状态依赖首选候选的路径、长度和修改时间。验证阶段发现的新增、删除、候选优先级变化仍会重新规划。
- 手动更新先核对旧清单的成员总数，再以最多 4,096 页为一批对照新计划和旧只读清单。相同来源、副本、页号、首选相对路径、长度、mtime 以及有效状态全部匹配时，沿用原发布代。匹配不全的更新继续走既有增量流程。发布清单、后端文件格式和提取配置身份兼容已有数据。

### 24 万页的独立阶段测量

G 盘为 KIOXIA EXCERIA NVMe SSD。6,000 个画廊各 40 页，用同一批目录和正常页数的元数据交叉运行新旧规划器各 3 次。测量使用实际规划代码、Windows 后台 I/O 优先级与 SQLite，每轮使用新的计划文件。以下为热缓存墙钟中位数。

| 测量范围 | 原版 | 优化版 |
| --- | ---: | ---: |
| 枚举并解析目录条目 | 3.232 s | 1.186 s |
| 初次计划，含目录读取与持久化 | 23.970 s | 7.449 s |
| 发布前无变化校验 | 8.304 s | 5.059 s |

初次计划包含目录枚举时间。逐行校验三张计划表，每轮 486,000 行，六份有序逻辑内容的 SHA-256 均为 `107e0344df4e29d04a127f4c64879dcfd1b3dea733b1850462d25ddec3c6a6ba`。原始样本在 `.qa/index-plan-20261122/` 的 `normal-before-final.log`、`normal-after-final.log` 和 `plan-equivalence.log`。

单独提取整库无变化判断的旧、新生产方法，以精简模型加载另一份 240,000 页合成清单，各预热一次，再交错测量 7 次。中位数 **27.577 s → 0.250 s**。这段从已有计划开始，包含枚举的完整更新时间需看应用测试。SQLite 查询计划显示旧清单按来源、副本和页号的主键匹配。原始样本在 `.qa/unchanged-index-20261122/benchmark.log`。

## 特征计算

- CPU FAST 在每格的栈缓冲中保留角点分数。用 16 位环形掩码找出符合最低阈值的九个连续像素，仅计算这些弧段的得分。一次评分即可确定强阈值或弱阈值回退的局部极大值。CPU 与 GPU 返回的候选都可按顺序直接追加，因为相邻格的有效区域互不重叠。
- CPU 和 GPU 路径都在 CPU 上构建图像金字塔。面积缩放遇到两轴缩小比例均在 1 和 2 之间时，复用每行的两至三行源像素，直接累加两至三列的贡献。逐项 double 乘法、加法顺序和取整规则与既有索引相同。
- 分离测试中，原版与优化 FAST 的完整 CPU ORB 摘要在 36 张图上逐组相同。NativeAOT 单线程每组 12 张 1200 × 1700 灰度图，预热后测四轮，仅修改 FAST 和角点收集时，线稿 ORB 中位数由 983 ms 降至 642 ms，密集纹理由 5,558 ms 降至 2,370 ms。这一组排除了磁盘、解码和训练。原始样本在 `.qa/index-cpu-20261122/`。
- 单独改变面积缩放，310 组像素结果相同，实际 RTX 路径下的八张线稿也产生相同的完整特征。每轮 30 次缩放，六轮取中位数，两次对照分别为 198.8 → 137.7 ms 和 198.6 → 115.9 ms。原始样本在 `.qa/index-resize-20261122/`。

### 测试边界与复现

三组应用流程调用 `AppServices.ImageSearch.BuildAsync`。H 盘样本刻意在计划提交后取消，只计从“正在枚举本地页图”到最后一批画廊计划提交的墙钟。页文件仅模拟目录条目，每页 3 字节，半数画廊带 `.ehviewer`。源目录在 Seagate ST3500418AS 机械硬盘，索引写入 G 盘 NVMe。系统文件缓存保持开启。完整建库的两组则使用 G 盘的 64 张不同线稿 PNG，每张 1200 × 1700，分属 8 个画廊。每个版本每轮新建资料库和索引，计时排除生成图片。CPU 组固定 4 个 worker、512 MiB；默认组自动使用 18 个 worker 和 RTX 5070 Ti。

变更更新用相同的 64 页基线，在不同画廊各新增、原位替换、删除一页，索引总数仍为 64。两条计算路径均应只解码 2 页，复用 62 页。全库无变化时应复用 64 页、解码 0 页。每次调用前后对照源路径、大小与 mtime，再对照不同版本的 `quantizer.bin` 和 `invlists.bin` 哈希。

`.qa/index-speed-20261122/` 保存本次基线源代码、探针源码、发布日志、基准程序与复现脚本。对同一批合成文件复跑时指定空闲目录。以下命令在仓库根目录运行，`$fixture` 可设为待测机械硬盘上的独立新目录。

```powershell
$qa = '.qa/index-speed-20261122'
$fixture = 'H:/.qa/ehviewer-index-replay'
& "$qa/PrepareFixture.ps1" -Path $fixture
& "$qa/Compare.ps1" -Fixture $fixture -Output "$qa/native-replay" -BuildKind native -Rounds 5
python "$qa/Summarize.py" "$qa/native-replay/samples.txt"
```
