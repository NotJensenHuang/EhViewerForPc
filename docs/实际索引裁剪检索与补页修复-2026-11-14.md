# 实际索引裁剪检索与补页修复（2026-11-14）

## 问题与结论

- 旧版每次搜索重新校验约 5.84 GB 的索引，并逐字段解压描述子；载入与查询共用 30 秒时限，实际裁剪样本在 30.02 秒取消。
- 清单只有 `member_state` 索引，按命中别名逐条查询会反复扫描 435,605 条记录。
- 实际已完成的六个补页任务共 202 页，图片均存在且签名有效；其中 GID 1675303、2367165 各保留一个零字节同页副本。旧扫描以「存在零字节文件」判定不完整，所以补完仍留在缺页分类，并可再次入队。
- 下载引擎在请求图片视图页前按原始页号跳过已有有效图片。修复保留该行为：获取画廊详情 / 页清单不等于重新下载已有图片。

## 改动

- `DiskInvertedIndex.ReadBucket` 按最多 1,024 条、每条 48 字节成批解压，保持记录顺序、边界检查、尾部检查及早退释放；不改变存储格式或距离计算。
- 查询服务串行管理当前查询，按冻结代保留已校验量化器和桶目录；每次核对指针、清单 / 后端元数据 / 量化器 / 倒排文件的大小和 mtime，文件变化或新代发布重新校验。缓存不长期持有文件句柄，不阻止旧代回收。
- 首次完整校验支持进度与取消，完成后才开始 30 秒查询时限；等待查询锁、校验和退出均受服务生命周期取消控制。
- 命中别名写入内存临时表，旧清单只顺序读取一次；按分数排序后只核对足够的有效结果，仍过滤停用源、路径越界、链接和已修改 / 删除页。真实清单以只读模式打开，不迁移或重建现有索引。
- 整页只有空文件时计入缺页；同页有非空候选时，空文件只保留诊断。旧头信息页数警告也独立于缺页分类。扫描缓存升级至 schema 4，自动重新生成；图片索引格式保持兼容。
- 单项和批量补页统一先检查原目录，已完整的副本同步库状态并跳过；保留已有任务去重与暂停 / 失败继续。补页完成后的库刷新独立于普通下载自动入库开关，清除完成任务后仍处理已安排的更新。
