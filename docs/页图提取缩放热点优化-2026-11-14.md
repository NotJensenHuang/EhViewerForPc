# 页图提取的缩放热点优化（2026-11-14）

用户更正慢的是“正在提取页图”，此前[训练批次修复](GPU训练批次与同步开销-2026-11-14.md)保留，但它不能解释或解决这个阶段的全部瓶颈。本次只优化提取阶段的首要已测热点，保持已有索引、规范化身份和描述子兼容。

## 诊断与反馈回路

使用现有 `GrayImage.Decode` → 规范化 PNG / SHA-256 / BLAKE3 → `OrbExtractor.Extract` 的真实调用路径。GPU 包装器只记录原 `TryGetFastScores` 的时间和调用次数；若任何 GPU 调用回退则直接判样本无效。固定种子生成 12 张线稿、12 张密集随机纹理，均为 1200 × 1700 灰度 PNG，每个类别独立计时两轮、2 个 CPU worker。每次 GPU 特征与本后端的完整 CPU 特征逐项相等。

三个候选原因是金字塔面积缩放重复计算、角点空间分布 / 集合开销、GPU 分层传输和等待。首次 JIT 线程采样仅归因于诊断阶段标记下的调用栈，结果约为：

| 方法 | 相关线程栈采样时间占比 |
| --- | ---: |
| `GrayImage.Resize` | 49.1% |
| `GrayImage.EncodePng` | 19.8% |
| `ImageKernels.GaussianBlur` | 7.9% |
| `ComputeSharpAccelerator.TryGetFastScores` | 6.0% |
| `GrayImage.Decode` | 4.0% |
| BLAKE3 压缩 | 3.6% |
| FAST 评分后筛选 | 3.3% |
| 角点空间分布 | 1.5% |

证据是 `.qa/extraction-gpu-20261114/baseline.nettrace` / `baseline.speedscope.json`。这属于线程时间采样，包含等待，不能当成硬件 CPU 或 GPU 利用率，也不能把多个并发 worker 的时间总和当作总耗时。

样本中，12 页有 96 次 GPU FAST 主机调用，GPU 主机段约 90–94 ms；线稿总提取约 0.70–0.74 s，密集纹理约 1.05–1.06 s。GPU 主机段还包括打包、上传、fence 和回读，实际 kernel 时间更小。CPU 缩放和规范化会在调用 GPU 之间制造空档，这与用户观察的低占用相符；本轮没有采集硬件 GPU 忙碌率，不能声称已复测任务管理器的百分比。

所有样本在内存中准备，计时不包括读取真实 HDD 文件、索引检查点提交、训练或构建。用户源库没有被扫描、修改或用于压测。

## 实现与兼容边界

旧面积缩放在每个目标像素的每个源像素贡献中，反复计算 x / y 边界和 `Min` / `Max` 权重。每层图像的几何关系不变，现改为：

1. 每次缩放预计算横向源起点、偏移和权重，所有行共用。
2. 每个目标行预计算纵向权重，所有列共用。
3. 像素乘法仍按原 `pixel * horizontal * vertical` 的逐项 double 顺序，累加仍先 sy 后 sx，保留原夹取和银行家舍入；没有改成分离卷积、FP32 近似或重新结合乘加。

临时坐标与权重使用本次同步调用独占的池化数组，在 finally 中归还；输出像素仍是独占数组，不携带租约，不跨 await / worker 共享临时缓冲。快路径限制两条源轴都不超过 16,384，覆盖解码器支持的图片；极端自建 `GrayImage`、放大、混合轴缩放及 Linear / Cubic / Lanczos4 都保留原路径。

按当前 .NET 11 ArrayPool 桶容量，快路径临时数组最坏约 1.25 MiB；实际索引已规范化至最长边 2048，通常更小，位于既有页估算固定工作区内。没有测分配减少比例，不能宣称零分配或将池预算当进程 RSS。

这是减少 CPU 重复工作以缩短提取时间，并未将规范化 PNG 编码、缩放、方向或 BRIEF 全部迁入 GPU。GPU 仍只加速 FAST 评分及训练分配。后续扩大 GPU 范围需要继续保持逐像素 / 描述子金样等价，不为提高显示占用率而改变提取身份。

## 像素与索引身份验证

- 修改前用 `8c3aaff` 的实际缩放生成七组固定像素哈希，覆盖分数比、接近 1 的缩放和单列结果；增加单轴半整数舍入、并发与池复用后的输出独占性。
- 2304 × 3072 随机灰度源规范化为 1536 × 2048，旧像素 SHA-256 为 `ccb615a35855f0bc785cf1b41b6bfad115dd0244f1b8b795dc50218f5ce1786f`，规范化 PNG SHA-256 为 `bbe2bf2e251b303fc5fce791d1bd141882e960fe6750dfade4d027386d157fb3`；两者保持不变。
- 用旧版实际 `GrayImage` 源码（仅改类名并去除重复枚举声明）与新实现直接比较，固定种子随机 3000 组，加 8 组轴长边界、细长图、单像素和放大，共 3008 组像素完全相同；`resize-fuzz.log`，源在 `fuzz/`。
- 新增 10 项回归先在旧实现通过，再在优化实现通过；未在测试里复制一份新算法来自证。

## 新旧 NativeAOT 对照

完整旧后端由 `git show 8c3aaff:<文件>` 导出全部受跟踪文件，项目包引用和版本相同；旧 / 新探针程序相同，分别引用旧后端和当前后端，发布至全新目录。没有用 JIT / AOT 混算收益，也没有用仅复制的简化缩放函数作性能样本。旧、新代码都使用相同 GPU FAST，训练批次修复也都存在。

生成样本、CPU 金样提取和 GPU 小样预热位于计时之外。计时覆盖解码、规范化 PNG / 哈希、完整 GPU ORB 及特征验证，不包含训练或库文件写入。墙钟时间为两轮范围，分阶段是两个并发 worker 的累计时间，二者不能相加比较。

| 样本 / 路径 | 12 页墙钟 ms（两轮） | CPU 时间 ms（两轮） | ORB 累计 ms（两轮） |
| --- | ---: | ---: | ---: |
| 线稿 / 旧版 | 1145.24 / 1151.38 | 1890.62 / 1937.50 | 1530.68 / 1538.97 |
| 线稿 / 新版 | 811.65 / 876.65 | 1312.50 / 1437.50 | 935.47 / 1012.65 |
| 密集纹理 / 旧版 | 1796.24 / 1788.74 | 2953.12 / 3031.25 | 1983.99 / 1994.69 |
| 密集纹理 / 新版 | 1535.76 / 1513.41 | 2531.25 / 2406.25 | 1476.24 / 1460.13 |

两轮平均墙钟耗时：线稿减少约 26.5%，密集纹理减少约 14.9%；平均 CPU 时间分别减少约 28.2% / 17.5%。ORB 子阶段累计时间分别减少约 36.5% / 26.2%。原始日志为 `aot-final-old.*.log` / `aot-final-new.*.log`，产物为 `probe-old-aot-final` / `probe-aot-final`。

24 张样本的完整特征按图前缀计数及 X / Y / 层级 / 角度 / 响应 / 32 字节描述子显式序列化，旧、新 AOT 摘要完全相同：`321acc58ff3d82bc9f39f7fc80f3093aa922ad62ba2e7b28b2f452792456162a`。每个 GPU 轮次仍与 CPU 特征逐项比较；每 12 页均完成 96 次真实 GPU FAST 调用。GPU 主机段总时间约 114–121 ms，未出现通过回退 CPU 得到相同结果的情况。

较早的 `aot-old` / `aot-new` 对照没有输出语料特征摘要，只作过程记录；以上以最终产物和日志为准。

样本为线稿和最坏压缩率的随机纹理，不能外推真实漫画、JPEG / WebP 解码或冷机械盘速度；仅验证本机 Windows x64 / .NET SDK 11.0.100 / RTX 5070 Ti。所有构建和运行均低优先级、限 2 个逻辑处理器，不创建 Win32 窗口，不操作桌面，不关机。

## 可复现命令

```powershell
$env:DOTNET_PROCESSOR_COUNT = '2'
$env:EHVIEWER_GPU_TESTS = '1'
dotnet test tests/EhViewerForPc.ImageSearch.Tests -c Debug
dotnet test tests/EhViewerForPc.ImageSearch.Ui.Tests -c Debug -p:PublishAot=false
dotnet run --project .qa/extraction-gpu-20261114/fuzz -c Release
dotnet publish .qa/extraction-gpu-20261114/probe-old -c Release -r win-x64 -p:PublishAot=true -o .qa/extraction-gpu-20261114/probe-old-aot-new
dotnet publish .qa/extraction-gpu-20261114/probe -c Release -r win-x64 -p:PublishAot=true -o .qa/extraction-gpu-20261114/probe-aot-new
dotnet publish src/EhViewerForPc -c Release -r win-x64 -p:PublishAot=true -o .qa/extraction-gpu-20261114/app-aot-new
```

所有运行统一通过 `tools/imsearch/Process.ps1` 的 `Invoke-ImsearchProcess`（CreateNoWindow、重定向和低优先级）。探针不带参数运行性能 / 特征对照，`goldens` 输出旧金样哈希。`probe/` 和 `probe-old/` 程序一致，仅工程引用的后端不同；原采样配置为本机 dotnet-trace 的 `dotnet-sampled-thread-time`，缓冲 32 MiB。
