## 本地搜索与"全量重建"的关系（分析，未改代码）

- 结论：本仓库无数据库（只有 settings/progress/library-cache-<id>.json + 封面 BMP 缓存），搜索是 `MainViewModel.ApplyFilter` 的纯内存 LINQ，不触盘、不触发 `LibraryScanner.Scan`。
- 搜索唯一引起的"重建"是 UI 层：`Galleries` 整体替换 → `GalleryListReplaced` → 回顶部 + `InvalidateMeasure`（ItemsRepeater 容器全量重建），确定性行为。
- "搜索后重建"的错觉：启动先用缓存出首屏，随后无条件做一次全目录校验扫描，收尾再整体替换一次列表；在扫描结束前搜索就会看到这次替换。判据是状态栏"（缓存 N）"——N≈总数=仅校验，N≪总数=真全量。
- 真会全量重建的四条路径：F5/刷新（`forceRefresh:true`）、缓存文件判无效（schema/RootPath/JSON 损坏→空缓存）、快照签名不匹配（目录 mtime、.ehviewer/.thumb 长度+mtime、页文件数、页长度和、页 mtime 最大值、最大页号）、数据源增删改。概率性来自盘符重挂载/时区 DST/SMB/exFAT 时间戳精度/备份工具改 mtime。
- 顺带发现的独立缺陷（未修）：`StopScanAsync` 只等 5 s，换源时若上一轮扫描未退出，`LoadLibraryAsync` 因 `IsScanning` 直接 return → 新源不扫描（列表空），重试即可恢复。

## GIF 帧率修复（用户反馈"gif 播放帧率太低"）

- 根因 1（主因）：`AnimationPlayer` 节奏为"先 Task.Delay(帧时长) 再解码"，实际间隔 = 帧时长 + 解码 + UI 派发。
- 根因 2：Windows 定时器量化 ~15.6 ms，`Task.Delay(80)` 约 93 ms 返回 → 80 ms GIF 上限仅 ~10.7 fps。
- 根因 3：每帧 `OpenRead` + `SKCodec.Create`（容器重新解析），有状态解码器无法顺序推进。
- 修复：`AnimationPlayer` 改为绝对时钟排程（deadline 累加，落后超一周期才重对齐）+ 解码与显示并行（先发起解码再等截止）+ 尾部 ≤3 ms `SpinWait` 抵消定时器量化；新增 `ImageDecoder.AnimationCursor`（单 FileStream+SKCodec，SemaphoreSlim 串行，Dispose 等待在途解码），整段播放复用。
- 冒烟素材改为 10 帧 × 80 ms、1280×1800（声明 12.5 fps），20 ms 采样 2 s 统计 `observedFps`，断言 `pacingOk >= 12×0.8`。
- 实测同素材：修复前 10.4 fps → 修复后 12.5 fps。44 单元测试通过，其余冒烟断言（非模态/滚动稳定/损坏页滚轮/进度恢复/26 容器虚拟化/卡片角标）保持。
- 局限：合成素材是整幅不透明帧，未覆盖 disposal=2/3、局部更新与透明叠加的 GIF（依赖 Skia 内部合成，只验证了帧推进与整幅颜色）。
- 产物：`artifacts/uismoke-gif-{before,fix,fix2,fix3,final}/`；`docs/TEST_REPORT.md` 新增 7.3 节。

## GIF 中段卡顿真因（真实样本 1592397，第二轮）

- 样本：`D:/BackUp/phoneGT5pro/ehviewer/1592397-(C97) [MIGNON WORKS (mignon)] My junior-animated`，实为 **GIF89a 但扩展名 .jpg**（EHViewer 常见伪装），9.8 MB、600×1067、75 帧 × 60 ms。
- 现象：逐帧解码 8.4 ms（f1）→ 201 ms（f74），74 帧累计 8.3 s；逐帧新建 codec 时 f60 已 215 ms → 播放中段必然卡死。
- 根因：GIF 增量帧 + `SKCodecOptions(frameIndex)` 未带 `PriorFrame` → Skia 每帧从文件头重建帧链。
- 修复：①`ImageDecoder.DecodeAnimationFrame` 常驻合成画布 + `SKCodecOptions(frameIndex, priorFrame)`，仅在回卷/回退时清空；②`AnimationFramePool`（静态池，`Release` 统一回收，MaxIdle=4）复用帧位图，`DecodedImage.IsPooled` + 幂等 Dispose；③动画解码绕开 `_normalSemaphore/_largeSemaphore`（单会话串行，共用会被页预取插队）；④`AnimationCursor` 持有 `_canvas/_canvasFrame`。
- 结果：3.0 ms/帧（max 8.5），74 帧 0.22 s；5 s 无窗口播放 82 帧/16.4 fps、最大间隔 60 ms；合成结果与「新建 codec 重建」逐像素一致（f2/f37/f74 均 0/640200 差异）。
- 新工具：`--anim-probe <file> [--out json] [--dump-frames dir]`（无窗口、只读），输出帧数/帧时长/逐帧耗时/循环回卷/逐像素合成校验/分配量/5 秒播放模拟。App.axaml.cs 在创建窗口前分流。
- 冒烟：合成动画页改为 30 帧 × 60 ms 局部更新+透明+disposal=1，新增 `maxGapMs`/`noStall` 断言；16.3 fps、最大间隔 63 ms，其余断言不变；44 测试通过。
- 注意：`AnimationFramePool.Clear()` 不在 `ImageDecoder.Dispose` 调用（关窗时渲染线程可能仍引用），缓冲随进程结束回收。
