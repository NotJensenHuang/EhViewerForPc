## .NET 10 → .NET 11 迁移（取消 SDK 固定）

- 删除根目录 `global.json`（原为 `version: 10.0.402` + `rollForward: latestPatch`）。触发原因：本机只装了 9.0.321 / 11.0.100，没有 .NET 10 SDK，项目目录内任何 `dotnet` 命令都报 "A compatible .NET SDK was not found"（退出码 155）。用户要求取消固定并迁移至 .NET 11。
- 三个 csproj 的 `TargetFramework` 统一为 `net11.0`：`src/EhViewerReader`、`src/EhViewerReader.Core`、`tests/EhViewerReader.Core.Tests`。`packaging/*.wapproj` 无 TFM，不需改；代码内无 .NET 版本条件编译。
- 文档：`README.md` / `PRODUCT.md` 同步 `.NET 11` 与 `net11.0` 输出路径；系统要求补记「不再锁定 SDK，需 .NET 11 SDK 11.0.100+」及 `runtimeconfig.json` 仅引用 `Microsoft.NETCore.App 11.0.0`（不依赖 WindowsDesktop.App）。`docs/PLAN.md`、`TEST_REPORT.md`、`FLUENT-MIGRATION.md`、`selftest-*.json` 属历史快照，保留未改。
- 验证（SDK 11.0.100）：Debug / Release 构建成功；`dotnet test` 129/129 通过；framework-dependent publish 与 NativeAOT publish 均成功（AOT exe 约 37 MB）；两种 exe 用 `--self-test` 均可启动到自检入口（退出码 2 是缺 `--root` 的预期行为）。
- 遗留项：`MainWindow.axaml.cs` 的 `_updatingLayout` 只写不读，编译报 CS0414（既有问题，非迁移引入，未改）；AOT 编译输出 FluentAvalonia / Avalonia 的 IL2073、IL2070、IL3050 警告，以及 ILC 对 Avalonia.Win32 DComposition `UnmanagedCallersOnly` 非 blittable 参数的 "will always throw" 提示，均属第三方库，产物正常生成。MSIX wapproj 仍需 VS 的 DesktopBridge targets，`dotnet build slnx` 依旧不可用（既有限制）。
- 若日后需可复现构建，可恢复宽松版 `global.json`：`{"sdk":{"version":"11.0.100","rollForward":"latestFeature"}}`。
