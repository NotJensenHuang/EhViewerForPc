## 横向连续模式 + GIF/WebP 动图（用户反馈第二轮）

- **用户设计决策**："双页模式"不做两页配对，改为横向连续模式（适应高度逐页横排）——因为无法预知哪页是"两页合并成一张宽图"，配对会拆错；合并页在横向模式下按原始宽度自然显示。
- **横向模式**：`ReadingMode.Double` 实现。`ContinuousPageItem` 增 `ResizeToHeight/Left/SlotWidth/ReadIndex`；VM 增 `HorizontalItems`（阅读序）+ `HorizontalDisplayItems`（RTL 反转后的显示序，绑定 UI）+ `GetHorizontalOffsetForPage/UpdateScrollOffsetX/SetContinuousHeight` + `HorizontalScrollToRequested` 事件；窗口增横向 ScrollViewer（StackLayout Orientation=Horizontal）+ `OnHorizontalWheel`（滚轮→横移，RTL 取反）+ 窗口尺寸变化同步高度。设置页三模式（单页/纵向连续/横向连续）。翻页 `Step` 复用，进度按页内偏移存取。
- **动图**：`ImageDecoder.DecodeFrameAsync(frameIndex)` 用 `SKCodecOptions(frameIndex)`；`DecodedImage` 增 `IsAnimated/FrameCount/FrameIndex/FrameDurationMs/Owner` + `DecodeNextFrameAsync`；`AnimationPlayer.PlayAsync` 逐帧循环（返回停止原因便于诊断）；`ZoomPanView` 与 `AsyncImage(Animate=true)` 接入；封面静态（Animate 默认 false）。帧对象不可变（init 属性），每帧是新 DecodedImage——控件持有"当前会话"引用逐帧替换。
- **踩坑 1**：SkiaSharp 2.88 无 `SKCodec.FrameInfos`，是 `FrameInfo` 数组属性；单帧图 FrameCount==0。
- **踩坑 2**：手写 GIF89a 的 LZW 编码器码宽递增时机：必须在赋值**前**检查新增表项值 `nextCode == 1<<codeSize`（解码器落后编码器一个表项），否则 Skia 拒解。用 Python 独立 LZW 解码器对照定位。
- **踩坑 3**：冒烟动画断言不能捕获 session 对象后反复读 FrameIndex（不可变），必须每轮从控件取当前会话采样。

- **踩坑 6**：AOT 发布中 MSBuild 调 reg.exe 查询 SDK 注册表被沙箱黑名单拦截，需非沙箱执行（产物正常）。

## 库界面滚动卡顿诊断（用户反馈）

- 滚动事件路径本身无同步阻塞（`OnLibraryScrollChanged` 仅存 offset；解码全部后台线程）。
- 嫌疑 1（最可能）：`AsyncImage.LoadAsync` 完成回调经 `Dispatcher.UIThread.InvokeAsync` 默认 Normal(9) 优先级投递，高于 Input(5)/Render(7)；快速滚动时大量封面完成回调（换位图+Dispose+InvalidateVisual）抢占输入与渲染 → 滚轮/拖滚动条被饿死。
- 嫌疑 2：封面无解码后内存缓存——AsyncImage detach 250ms 后释放位图，CoverService 只缓存 fallback 路径字符串，来回滚动每次重新读盘解码，产生持续 I/O/GC 压力与弹入。
- 嫌疑 3（环境）：`UseWin32().UseSkia()` 下若 ANGLE 初始化失败会静默回退软件渲染，缩放位图+圆角裁剪逐帧重绘会明显卡。用 DevTools(F12) 或 Win32PlatformOptions 显式指定 RenderingMode 验证。
